# サンプル発送依頼システム 要件定義書

## 1. 概要

取引先から依頼された商品サンプルの発送を、社内で承認・手配するためのWebアプリケーション。
申請者が依頼書を起票し、複数段階の承認を経て、最終的に事務局担当者が発送手配を行う。

## 2. 申請フロー

```
申請者
  └─ 下書き作成・提出
       ↓
部門長承認
       ↓
受付（承認）
       ↓
二次承認
       ↓
総務部長承認
       ↓
手配待ちボックス（事務局担当者が発注・手配）
       ↓
完了
```

- 各承認ステップで担当者は「承認」または「却下（差し戻し）」を選択できる。
- 却下時は**却下理由の入力を必須**とし、申請者に差し戻す。
- 差し戻された申請は申請者が内容を修正のうえ、部門長承認から再提出する。

## 3. ステータス一覧

| ステータス | 説明 |
|---|---|
| 下書き | 申請者が入力中、未提出 |
| 部門長承認待ち | 提出直後 |
| 受付待ち | 部門長承認済み |
| 二次承認待ち | 受付済み |
| 総務部長承認待ち | 二次承認済み |
| 手配待ち | 総務部長承認済み、事務局の対応待ち |
| 完了 | 手配完了 |
| 差し戻し | いずれかの承認者が却下、申請者の修正待ち |

## 4. ロール定義（1ユーザーが複数ロールを兼任可能）

| ロール | できること |
|---|---|
| 申請者 | 新規申請の作成・下書き保存・提出、差し戻された自分の申請の再編集、自分の申請一覧の閲覧 |
| 承認者（部門長／受付／二次承認／総務部長） | 自分宛ての承認待ち一覧の閲覧、承認／却下（却下理由入力） |
| 事務局担当 | 手配待ちボックスの閲覧、手配完了操作 |
| 管理者 | 部門マスタ・承認者マスタ・ユーザーアカウントの管理 |

## 5. フォーム項目（サンプル発送依頼書）

| 項目 | 内容 | 備考 |
|---|---|---|
| 申請者情報 | 氏名／所属部署 | ログインユーザーから自動取得 |
| 送付先情報 | 会社名／担当者名／連絡先 | 発送先住所もここに含む |
| 依頼内容 | 依頼を受けた経緯・用途 | 自由記述 |
| サンプル品目 | 品名／度数／容量／本数 | 複数行入力可 |
| 到着希望日 | 日付 | |
| 添付ファイル | 取引先からの依頼メール、見積書等 | |
| 備考 | 自由記述 | |

## 6. マスタ管理

- 部門階層はシンプルな1階層（部門 → 部門長）とする。
- 部門・承認者（部門長／受付／二次承認／総務部長）・ユーザーアカウントは、管理者が管理画面から登録・編集できる。
- 承認者は組織階層（ユーザーの所属部門）から自動的に判定される。

## 7. 認証

- メールアドレス（ID）＋パスワードによるシンプルなログイン。

## 8. 通知

- メール通知は行わない。関係者は各自ログインし、一覧画面（承認待ち一覧・手配待ちボックスなど）で状況を確認する運用とする。

## 9. 技術方針

- 少人数チームでの利用を前提とした、シンプルな構成で実装する（具体的な技術スタックは次のステップで選定）。
